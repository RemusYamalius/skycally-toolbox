## Plan: AI Email Writer tool at `/tools/ai-email-writer`

### Important correction before we start

The brief says "same direct client-side fetch pattern as ai-cover-letter-generator — NO createServerFn". That's not what the cover letter tool actually does — it imports `generateCoverLetter` from `@/lib/ai-cover-letter.functions.ts`, which IS a `createServerFn`. Direct client-side calls to `ai.gateway.lovable.dev` would need `VITE_LOVABLE_API_KEY`, but Lovable only provisions `LOVABLE_API_KEY` (server-only). Shipping the gateway key to the browser would also let anyone drain your credits from the built JS bundle.

**Recommendation:** mirror the real cover-letter pattern — a `createServerFn` in `src/lib/ai-email-writer.functions.ts` + a client route that calls it with `.then/.catch/.finally`. Same "no async arrows, no `useCallback(async)`" build-safety rules apply, and everything else in your brief (UI, SEO, FAQs, etc.) stays identical.

I'll proceed with that unless you tell me to force the raw client fetch anyway.

### Files

1. **`src/lib/ai-email-writer.functions.ts`** (new)
   - `createServerFn({ method: "POST" })` with Zod `inputValidator` for: `emailType` (8-enum), `yourName`, `yourRole?`, `recipientName?`, `recipientRole?`, `keyPoints`, `context?`, `tone` (6-enum), `length` (short|standard|detailed), `language` (5-enum), `includeSubject` (bool).
   - Handler builds system + user prompt (exact text from brief), POSTs to `https://ai.gateway.lovable.dev/v1/chat/completions` with `Lovable-API-Key: process.env.LOVABLE_API_KEY`, model `google/gemini-2.5-flash` (2.0-flash-001 isn't on the Lovable catalog; 2.5-flash is the closest supported fast Gemini — swap in if you'd prefer `google/gemini-3-flash-preview`).
   - Status mapping: 429→`RATE_LIMITED`, 402→`CREDITS_EXHAUSTED`, else `GENERATION_FAILED`. Returns `{ email: string }`.

   - `DEBOUNCE_MS = 500` gate via `useRef<number>`.

     - `ToolPageShell` wrapper (title + description).
