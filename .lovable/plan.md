# File Viewer — /tools/file-viewer

A universal, 100% client-side viewer for Word, Excel, PDF, TXT, Markdown, and CSV files. Matches existing Skycally patterns (ToolPageShell, HowToUse, ToolSeoContent, RelatedTools, DropZone, buildToolMeta/toolBySlug).

## Files to create / edit

1. **Create `src/routes/tools.file-viewer.tsx`** — the full tool route, using `createFileRoute("/tools/file-viewer")` + `buildToolMeta(toolBySlug("file-viewer", tools))`.
2. **Edit `src/lib/tools.ts`** — add `FolderOpen` import + `file-viewer` entry after the `pdf-reader` entry, with `category: "utility"`, `categories: ["utility","pdf","text"]`.
3. **Edit `src/lib/related-tools.ts`** — add `"file-viewer": ["pdf-to-word","word-processor","pdf-reader","pdf-text-extractor","image-to-text"]`.
4. **Install `marked` + `dompurify`** via `bun add marked dompurify @types/dompurify` for Markdown rendering and safe HTML sanitization (mammoth/marked outputs).
5. `src/routeTree.gen.ts` will be auto-regenerated by the TanStack plugin.

## Library plan (all client-side)

- DOCX → `mammoth.convertToHtml({ arrayBuffer })` with `convertImage` to inline base64 images. Sanitize with DOMPurify before injection.
- XLSX/XLS → `XLSX.read(buffer,{type:"array"})`, render the active sheet with `XLSX.utils.sheet_to_html`, sanitize, then apply table styling via wrapper classes. Tabs above the table for `workbook.SheetNames`.
- PDF → `pdfjs-dist`, lazy render visible page ± 1 via IntersectionObserver, max 5 concurrent canvases, zoom 50–200%, cap canvas dimension at 4096px.
- TXT → `FileReader.readAsText`, `<pre className="fv-pre">`.
- MD → dynamic `import("marked")` (added as a dep), fallback regex if it fails; sanitize and render in `fv-prose`. Rendered/Raw toggle.
- CSV → manual parser handling quoted fields with commas/escapes; first 5000 rows cap with notice.

## Component structure

Single route file (~600 LOC) organized as:

```text
FileViewerPage
├── empty state (DropZone + format badges + privacy + sample buttons)
├── loading state (skeleton + filename, PDF page progress)
└── loaded state
    ├── Sidebar (260px desktop / bottom-drawer mobile via ℹ button)
    │   ├── file icon + name + size + type badge
    │   ├── PDF page nav / Excel sheet tabs
    │   ├── PDF zoom controls
    │   ├── Copy Text + Open Another File
    │   ├── word/line/row counts
    │   └── RTL/CJK detection badge
    └── Main viewer (white card, scrollable)
        └── Renderer per type (DocxView / XlsxView / PdfView / TxtView / MdView / CsvView)
```

## Detection & i18n

- `detectRTL(text)` exactly as specified (>20% RTL chars triggers `dir="rtl"` + right-align).
- CJK detection adds `font-family` fallback to the viewer container.
- Sample buttons load hardcoded in-memory demo content (no real files): a tiny HTML snippet for "Word", a 2-sheet hardcoded array → SheetJS workbook for "Excel", and a generated single-page PDF via pdf.js (or use a tiny base64 sample) for "PDF".

## Error handling

Try/catch around every loader path; map known errors (size > 50MB, encrypted PDF via pdfjs `PasswordException`, mammoth/SheetJS parse errors, empty file) to the user-facing messages from the spec, shown in a red banner inside the viewer with "Try Another File".

## Styling

- All colors via CSS variables; file-type accent colors injected inline as the spec lists (these are functional brand colors for file-type icons/badges only — kept as inline style, not Tailwind utilities, so they don't leak into the theme).
- `fv-prose`, `fv-pre`, `fv-table` scoped CSS added inside a `<style>` tag inside the route component (matches pattern used in other Skycally tools that need scoped styles).
- Mobile: sidebar becomes a Sheet drawer (shadcn `Sheet`) toggled by a floating ℹ FAB.

## SEO / How-to / Related
